# Diagrams

Mermaid sources are authoritative; SVGs under `docs/assets/` are generated by the existing renderer. Each source carries accessible title/description text and each source/SVG pair is SHA-256-bound in `manifest.json`.

```sh
python experiments/render_diagrams.py
python experiments/render_diagrams.py --check
```

Rendering uses pinned Mermaid CLI through Node/npx and a supported browser (`BLABLA_CHROME` can select it). The renderer adds an opaque white background/padding for readable dark-page display. Inspect the actual SVGs after rendering; `--check` verifies hashes and accessibility metadata, not visual quality. Never hand-edit generated SVGs.

This set used the unmodified Mermaid CLI 11.4.2 `renderMermaid` function with its resolved Mermaid 11.17.2 dependency, rendered in Playwright 1.63.0 WebKit because Chromium could not open process sockets in the build environment. The existing renderer's `opaque()` and source/SVG hashing were then applied unchanged. Browser layout may change pixels; the sources and text alternatives define the semantics.

## concept

Owner intent enters project.bla as two distinct surfaces. Behavior and Structure contracts are executable; Mission, System, Process, Knowledge and Goals are queryable memory. Humans and coding agents use status and explain to recover relevant context, then change ordinary implementation code. finish checks the implementation against the active contracts; only those checks decide OVERALL GREEN or BLOCKED.

## architecture

The CLI and project layer compose two independent verification pipelines: behavior parsing and typed IR feed a finite campaign through the trusted application adapter; structure parsing feeds static source providers and one fact evaluator. finish combines fresh canonical behavior and live structure into OVERALL. Alongside them, memory feeds queries, task records feed deterministic challenge, and explicit host checkpoints feed bounded expert policy and optional advice. These non-gating surfaces never decide completion.

## agent-workflow

The orchestrator recovers relevant intent with status and explain, then opens a bounded task. The worker accepts, implements within scope, records focused evidence and lens assessments, challenges the record and hands back ready. An independent reviewer inspects the diff and evidence and records findings; corrections return through acceptance and renewed evidence. The orchestrator resolves findings, integrates, confirms owner records and closes when current, then runs finish. Optional expert advice enters only at observed eligible checkpoints and has no scope or gate authority.
