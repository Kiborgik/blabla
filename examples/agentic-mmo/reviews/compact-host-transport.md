# Compact hosted observation transport

Actual author: gpt-6-astra/xhigh, server owner. Prospective specification and implemented transport, 2026-10-16. The initial tests/report-only slice was expanded by the parent after receipt closure; the worker selector and README are now implemented under that accepted scope.

## Deciding boundary

Reuse the approved pure `observeCompactTrade(state, seat, timestamp)` projector. Accept optional `observationFormat: "compact-trade-v1"` on MCP `observe_world` and `GET /api/observe`. Omission preserves the existing complete response, including its duplicate `choices` alias. The explicit compact result keeps every canonical ordered action, adds its zero-based `choice` index inside each `legalActions` entry, and omits only that duplicate alias. Preserve server timestamp, release/features, calendar, admission, plans, stored trade terms and all other observation fields.

Reject any other selector with HTTP 400 / `invalid_observation_format` before database access. This includes null or non-string MCP values, empty/unknown/whitespace-suffixed strings, and ambiguous repeated HTTP selector parameters. Never silently fall back. Public observation access stays public; MCP’s existing origin guard and mutation enrollment remain unchanged. Selecting a presentation format is not a release or authorization change.

The minimal deciding implementation is in `server/worker.ts`: one early selector check, the canonical projector import, one observation branch and discovery/query forwarding. Repository, engine, action admission and persisted schemas need no change. Existing numeric action admission remains revision-strict, and the compact array uses exactly the same canonical order. The format never submits or reserves an action.

## Research and next decision

This transport specification reuses the approved source-grounded [core design](compact-trade-observations.md), the canonical projector and current worker/repository implementation. MCP’s read-only annotation remains a hint rather than authority; the established [MCP tools contract](https://modelcontextprotocol.io/specification/2025-06-18/server/tools) supports the existing structured/text result wrapper. No new runtime API, dependency, endpoint, database query shape or provider quota assumption is needed.

Independently review the selector-only worker change against the genuine prospective failures and combined compact/hosting/receipt regressions. Verify source/deployed discovery separately before claiming native compact support. No live action, uncertain-command retry or release activation is part of this work.
