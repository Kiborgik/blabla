# Feature contract binding review

Reviewed on 2026-10-16 by actual gpt-6-astra/high. Accepted for bounded integration review with no blocking finding. I authored portions of the underlying engine, planning and frontier behavior, but did not author this adapter/probe patch. This is an independent review of the binding delta, not an independent reimplementation or a fresh audit of the whole engine.

## Observed binding

`FeatureProbes.reset` creates separate seeded worlds through actual compatible release commands. It obtains the founding action from actual legal actions and fails if the expected explicit source is unavailable. It does not edit stocks, population, technology or feature flags to manufacture eligibility. Concurrent commands and founding commands use actual `applyCommand`; accepted flags come from the returned result. Observation fields project resulting worlds, and founding payment sums actual resource debits in hundredths rather than copying a promised cost. Refused commands retain the returned engine world.

The peer fixture holds seat0 idle while seat1 uses a real independent allowance. Ten-second feature windows call actual strategic catchup; the test compares the one-minute boundary against the real engine result. The timestamp starts at a fixed UTC epoch and advances by the canonical tactical interval. Founding deliberately uses its separate fixture's fixed epoch, so advancing the concurrent clock cannot manufacture frontier production or population growth. Reset and identical action sequences are deterministic, and exposed test snapshots are detached.

Plan sizes0–2 become actual attached plans on a submitted wait action. Unsupported integers are mapped to one bounded three-item invalid request; a hostile requested size never drives allocation. Accepted successor metadata remains needs-review and is never automatically executed. The wire observation `actionable_plan_items` counts all stored plan items, including the completed head: it supports the contract's maximum-two bound, not a claim that both items remain executable. The test exercises negative, oversized and maximum-safe-integer sizes. Fractional/non-number wire arguments are rejected by the existing Adapter integer parser; unsafe integer inputs that reach the helper are bounded there.

## Isolation and provenance

Feature fixtures stay in memory and never call the durable campaign store's submission or authored-transition paths. Existing sequential campaign observations keep their original names; new fields use concurrent/frontier prefixes except the explicit feature and plan signals. The integration test snapshots the durable campaign before feature calls and compares it afterward, then verifies that ordinary hold still advances the sequential campaign with contract-probe provenance. There is no fabricated development-agent model identity, receipt, public activation or durability claim for feature fixtures.

## Evidence and limits

Ran exactly `node --test tests/contract-features.test.ts`: all eight focused tests passed, and the complete child log was read. The first evidence attempt was refused because the reviewed-target fingerprint changed; the current target was reaccepted before the successful run. No broad suite was rerun by this reviewer. Author-reported initial missing-module failure is correctly described as harness-admission evidence, not semantic falsification.

The concurrency and frontier draft clauses now observe executable positive and refusal paths. Their scalar assertions remain narrower than all engine invariants: revision equality alone is not full-world immutability, and summed payment is not a per-resource accounting specification. Focused tests additionally compare full worlds for relevant sequences. These bindings do not establish arbitrary-hostile-command coverage, live model play, production-operation contract meaning, or a missing strategy contract. Contract promotion, canonical finish and the remaining production/strategy definitions remain owner decisions.
