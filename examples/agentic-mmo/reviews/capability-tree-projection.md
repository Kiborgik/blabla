# Canonical capability tree projection

Actual gpt-6-astra/high. Implements the owner-requested bounded core seam; Art owns the spectator rendering. No state schema, release, content tuning, server or UI source changed. Resident prospective RED remains untouched.

## Delivered API

`core/capabilities.ts` exports `capabilityCatalogue()`, `projectCapabilities(state, civilizationId, cityId, timestamp, choices?)`, and the catalogue, projection, row, blocker and choice-context types.

The detached catalogue retains all nine technologies, eight buildings, seventeen prerequisite edges, feature definitions with registered release references, releases, eras and milestone definitions. Actual source descriptors supply costs, recurring inputs, base outputs, effects and prerequisites without copied production tuning.

The projection contains actual revision/time/release/features, selected civilization/city, separate admission information, all research/build rows, achieved/eligible milestone facts and the exact persisted bounded intent when one exists. It does not invent motives or certify a recorded follow-up as freshly ready. Current research remains Available with actual progress and no duplicate action; Done construction remains exact-town-specific, with paused/blocked operation receipts separate.

Default projection performs no legal-action or trade-menu enumeration. It explicitly returns `choiceReferenceState: 'not-provided'`, empty actions and unavailable references. An optional existing canonical list carries `{revision, observedAt, seat, legalActions}`; equal context is required and exact detached options/indices are retained with `choiceReferenceState: 'provided'`. A supplied empty menu remains distinguishable. This checks context metadata, not the semantic authenticity of arbitrary caller-created options; the caller must supply its existing canonical list. Art uses the inexpensive default.

## Shared rules and compatibility

`core/simulation/capabilities.ts` extracts research/build eligibility and typed blockers, and `availableActions` consumes the same helpers. Research still has no science-balance or era-metadata selection gate. Construction retains actual feature, technology, era, shared resource and selected-city/site requirements. Specialized actions remain exact-city actions. Older untargeted construction remains first-eligible-city behavior; the tree reports a legacy-target blocker for another selected town instead of inventing an exact action.

Status priority is completed fact, missing applied feature, other structural blocker, available. Missing features distinguish registered-release support from catalogue-only data without claiming deployment readiness. Navigation remains planned despite released land trade. Temporal admission and outcome stay separate from structural status. Milestones reuse `milestoneEligible` with empty pending events against committed facts; year does not manufacture an achievement. Full public choice/outcome history joins remain Art/transport work, not newly inferred core facts.
