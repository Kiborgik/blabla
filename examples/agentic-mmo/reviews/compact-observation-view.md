## Semantic preservation

`observeCompactTrade` starts with the ordinary `observe` result. That result is deeply detached through `structuredClone`; changing the new result's trade reasons does not change world state, the ordinary response, admission, plans or legal actions. The projection leaves each complete action and label in place and shortens only proposal and accepting-response reasons. Non-trade explanations retain their ordinary meaning. It neither truncates options nor replaces typed commands with table indexes.

Town references come from visible pending offers, visible agreements, relevant plan actions and legal trade actions. Towns are deduplicated and sorted by canonical ID. Exact-endpoint proposals use their named towns; older releases retain the existing first-city interpretation with that fact explicitly stated. Missing cities or tiles are omitted rather than substituted. The missing-source plan test deliberately edits a component fixture and verifies the same derived invalidation as ordinary observation; it does not claim a legal city-destruction journey.

For each referenced existing town, identity, owner, name, tile, terrain and deposit are read from canonical state. Shared `siteProduction` supplies the combined site output. Terrain output follows the same feature gate, the deposit component is the remainder, and the six-resource base vector adds the shared base production. The regression covers every resource deposit and both terrain-gate states. The common semantics explicitly place these values before focus, productivity, buildings and upkeep, so they are not represented as net stock changes or operating receipts. The preceding duplicated deposit calculation has been removed.

Current recipe facts are released and referenced proposal catalogue entries, cloned with all construction, cargo, upkeep and commerce vectors. They do not replace pending-offer or accepted-agreement snapshots. The isolated tuning test changes current recipe cargo and confirms both historical snapshots retain their original terms. Acceptance reasons point to the named pending offer. Observation-local reference IDs never become new command or plan fields.

The existing two-item action plan and original observation context are preserved. Formatting does not execute a follow-up, consume an action opportunity, advance a strategic beat or change the calendar. The default core `observe` remains unchanged and has neither new field. The compact projection is an explicit separate function at this reviewed boundary; unknown transport selectors are not handled by this core change.

## Measured scope

The final author check measured deterministic synthetic fixtures at fixed seed and timestamp:

- Five cities, four proposal choices: ordinary 10,660 UTF-8 JSON bytes; compact 11,094 bytes. This is 434 bytes larger, about 4.1%, because small worlds have little repeated geography and the new table includes complete recipe obligations.
- Twenty-five cities, all 100 exact proposal pairs retained among 122 choices: ordinary 96,247 bytes; compact 52,378 bytes. This saves 43,869 bytes, about 45.6%.

The finite 25-city regression requires a meaningful reduction relative to its ordinary baseline. It is not an arbitrary-world envelope, token count, latency result or deployment benchmark. The earlier design prototype reported different numbers; the values above are the actual implemented fixture results.

The implementation still constructs the full ordinary observation before factoring it. It therefore retains the existing Cartesian action generation and repeated full-prose construction work, then performs projection work. The result supports a smaller transmitted/model-read payload in this fixture; it does not establish faster generation or remove quadratic work. There is no silent pagination, loss of exact pairs or hidden size-triggered format switch.
