## Procedural runtime and development roles

The owner-directed runtime uses seeded generation and weighted finite-state civilizations plus a procedural Director, not language-model players. Development agents build the game through BlaBla and no longer take civilization seats between tasks. Controllers only choose authoritative legal commands; preserve resource costs, active commitments, consent, release gates and exact receipts. Shared-host activation remains explicit. The local observatory is a separate accelerated browser simulation, clearly labeled and persisted without overwriting the native world or its history.

Civilization games are the hard UI/UX reference: a map-first inhabited world, legible geography and borders, recognizable city growth, actual productive sites/routes and meaningful event consequences. Original assets only. No player world-changing controls. Camera, inspection, layers and playback remain observational.

All current implementation streams use actual Astra/xhigh. Roles have primary specialties but can accept useful disjoint cross-role work through an explicit BlaBla handoff. Never review your own patch or misstate another coordinator's model. Preserve historical model attribution.

Group tests and independent reviews after meaningful feature batches, not every small edit. Run the declared finite check at the feature boundary, rerun narrowly for a concrete failure or materially changed evidence, and obtain canonical integration verification before completion. Hourly commit-readiness inspection does not force a commit or rerun. Proactively record concrete BlaBla friction and implement useful bounded tool improvements without weakening gates.

Existing authorization denials remain exact held intents; a changed command ID, caller or wrapper does not clear them. Definite zero-effect stale-revision refusal may use the documented same-intent CAS route after a fresh read. Reconcile uncertain actions through receipts before retrying.

## Publication

Publish only game code, tests, contracts, assets and useful project documentation. Keep internal reviews, hourly status, handoffs and raw verification evidence in local BlaBla records or scratch. A source acceptance, deployment and actual civilization outcome are distinct; record their evidence without adding report-only files to Git.
