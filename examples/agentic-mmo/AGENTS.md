# Agentic Civilizations

Read the repository AGENTS.md and invoke `.claude/skills/blabla/SKILL.md` first. This nested project has its own task ledger and goals. Use current-source Cargo commands from the repository root:

    cargo run --locked --quiet --bin blabla -- --project examples/agentic-mmo status
    cargo run --locked --quiet --bin blabla -- --project examples/agentic-mmo task show NAME

Accept the assigned task with your actual model before editing. Only edit its scope. Every worker shares one branch; only the orchestrator changes Git state, shared interfaces, contracts and integration files. No comments or docstrings in source code.

Evidence commands may exit zero while a child check failed. Read the child's exit and full log. Record focused checks, lenses and findings; challenge then hand back. Only the orchestrator closes tasks and runs finish.

Humans only watch. Do not add world-changing browser controls. Keep the core deterministic and independent of rendering. Replays identify whether actions came from built-in policies or development agents. Never claim scripted data is live model play.

## Ordinary actor turns and Director decisions

Each actual civilization owner chooses its own ordinary supported research and exact-town construction between work units, using a fresh authoritative read and at most two immediate planned items. The director-event flow requires Creative Director consultation for World Director events and targets. Shared catch-up or overlapping world writes require explicit coordination; this does not create a new per-build Creative approval requirement for independent ordinary actor turns. Preserve any narrower requirement already attached to an individual assignment. Existing reviewer denials remain exact held intents until their required authorization route is satisfied; changing the command ID, caller or wrapper never clears a denial. A definite zero-effect stale-revision refusal may follow the documented same-intent CAS path after a fresh read. Uncertain actions are reconciled through receipts before any retry.

## Publication

Publish only game code, tests, contracts, assets and useful project documentation. Keep internal reviews, hourly status, handoffs and raw verification evidence in local BlaBla records or scratch. A source acceptance, deployment and actual civilization outcome are distinct; record their evidence without adding report-only files to Git.
