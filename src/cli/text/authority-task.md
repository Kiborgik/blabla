A bounded task is the record of what an orchestrator decided, held against the working tree. It is machine state rather than project memory: it reaches no layer and never decides completion. Write scopes are normalized project-relative paths and may not overlap any nonterminal assignment, including READY; read inputs may overlap. Task mutations use an exclusive cross-process record lock and atomic record replacement. An orchestrator withdraws an assignment with task withdraw NAME --reason TEXT --model MODEL; WITHDRAWN is terminal, releases ownership and grants no completion credit. Changed paths remain project challenges until restored to their pre-task digests or explicitly reconciled through task reconcile-withdrawal NAME PATH --successor TASK --model MODEL against current successful evidence from a CLOSED successor. Withdrawal history remains auditable and reconciliation can become stale.
