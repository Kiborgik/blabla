## Deciding boundaries

- Preparation opens and accepts two actual source tasks, records their actual successful check and Partial claim, and opens one reviewer with primary work and explicitly additional secondary. The initial other-source verdict is recorded through the CLI. No persisted verdict or close is directly fabricated.
- Eligibility is computed before the deciding operation from declared source identities, actual review and claim currentness, accepted reviewer/model, current permitted-model policy and tracked check readiness. The finite preparation selector chooses a scenario, not a pass boolean. There is no trial invocation of the deciding action used as an oracle.
- Source-input drift and referenced-artifact-only drift are distinct. The latter deliberately leaves the recursive target revision current while the selected claim becomes stale. Reacceptance, wrong model, already READY reviewer and existing unassigned source exercise separate reached refusals. This is a finite predicate projection for these controlled fixtures, not a claim of independently exhaustive lifecycle eligibility.
- The deciding command includes the selected source. Success requires an actual task result; only task-category exit 2 is a lifecycle refusal. Compiler, signal, timeout, malformed JSON and other error categories stay adapter failures. The stored accepted verdict is joined to exact selected source, goal and current claim digest.
- Both complete fixture trees are compared around refusal. Any refused write becomes an adapter error. Successful actions independently compare source-task bytes and nonselected verdicts, and repeated selection retains two separate same-goal source rows rather than overwriting the other source.
- Batch and legacy fixtures own separate temporary projects. New/reset/untouched observe initialize no filesystem or subprocess fixture; reset drops both. The first explicit review can lazily build a real default fixture, but the preceding observation reports uninitialized and the action does not claim unchanged bytes. Malformed selectors fail before fixture construction, signed extremes map to eight finite scenarios, and two probe instances remain independent.
- Legacy handlers merge only their own view fields. Shared terminal fields are reset for each action; retained batch facts cannot be mistaken for a new legacy result. The focused tests exercise both directions of alternating fixture use.
