# Receipt-relative task freshness

Actual implementation: gpt-6-astra/high, 2026-10-16. Implements the accepted
`reviews/precise-freshness-feedback.md` first slice without new persistence.

## Result and authority

`task freshness NAME [--identity ID] [--json]` routes before the record lock.
It takes one current task snapshot and reads actual recursive target records.
Existing intent, reflection, check and review currentness functions remain the
authority. No schema, revision hash, source acceptance, READY refresh or close
predicate changed. Skeptic reconciliation and matching blunt renderings now
point to the diagnostic; their statements/classes and authority remain intact.

Shared comparisons are keyed by complete recorded/current revisions, context,
owner and selection overrides. Paths retain absent-key versus present-null
membership. Invalid model/status/reason remain separate from revision equality.
Checks use the latest matching receipt, or explicitly identify the latest
nonmatching historical receipt. Check assignment history is unavailable; a
legacy missing epoch is explicitly unavailable. Reflection/review composite
assignment differences never become invented statement/scope/evidence fields.

Opening children are eligible only when their actual aggregate equals the
receipt digest and the current selected digest matches. Conservative filtering
refuses expansion when historical attribution cannot safely be reconstructed.
A direct file is not presented as a directory baseline. Missing members denote
tracking-set changes, not physical deletion or unreadable-file certainty.

All principal collections cap presentation at 50 with complete counts. Child
rows share a global 50-row budget across displayed groups and sorted roots;
counts still include matching roots hidden by the path cap. Child counts are
per receipt comparison, not unique physical files. Unavailable totals stay null.
Memory/work scale with existing tracked files and retained receipt contexts;
no second tree is read per identity. This slice does not add future baselines.

## Deciding evidence and limits

The initial seven prospective CLI cases all failed on the genuinely missing
`freshness` command: scratch `missing-command-red.log`. The first log-redirection
attempt lacked the scratch directory and did not execute a test; it is not RED.
One transient private-visibility compile error was corrected immediately; the
current-source CLI then compiled and the seven runtime cases passed.

A later concrete cap counterexample failed with available child total50 instead
of60. `child-cap-red.log` preserves it; counting all selected roots before display
capping corrects that omission. The initial expanded refusal control used an
incorrect bounded flag; it was corrected to actual `--bounded` and now requires
a task-policy refusal, never a parser failure. Original logs remain retained.

The focused suite covers missing/current/grouped receipts, exact matched children
(add/change/remove), unavailable opening boundaries, identity filtering and
invalid claims, epoch/opaque assignment drift, reflection-only receipt changes,
check drift, missing-null membership, recursive stale/missing/unreadable/cyclic
reviews, closure-only versus withdrawal bookkeeping, 60-child/path/identity
counts, symlink/ignored/outside paths, exact byte-preserving reads, unchanged
challenge/READY-refresh/ordinary/bounded refusals, absent-storage reads, and
actual successful ordinary and bounded closure over tiny genuine fixture runs.
Corrupt/legacy bookkeeping fixtures are explicitly constructed test records;
they do not fabricate successful checks or production evidence. Closure-positive
fixtures execute real canonical checks and preserve status bytes/result basis.

Five existing voice tests pass, including complete neutral-statement retention
and exactly one blunt rendering per class. The final declared check is only
`cargo test --locked --test task_freshness`; it is the current targeted evidence,
not a whole-project verification. No global campaign or contract promotion ran.

A read-only real compact-review diagnostic returned36 receipts in4 groups,
18 available child comparisons,15489 JSON bytes, in0.136s local elapsed time.
Every current example task and existing status file retained identical SHA256
bytes. Full output/metrics are in this task's scratch `dogfood.json` and
`dogfood-metrics.json`. This is one local sample, not a capacity guarantee or a
measured reduction in total review effort. No historical effort is reconstructed.
