## Implemented boundary

`bridge/source_cli.rs` provides one lazy request object shared by actual lifecycle invocations in singular/batched delivery, bounded results, ready receipts and task-role resolution. Each recognized request retains its original 4500 ms total allowance. Construction/reset/invalid actions and observations that do not require CLI execution do not build. Existing tests and five-second AppSession assertions remain unchanged; the five importing test files receive only shared-module registration.

The ordinary supported path runs locked Cargo with JSON output, requires successful process/build completion and exact canonical manifest/bin/source/executable provenance, and makes a request-owned executable copy. It preserves the original filename and mtime for existing writer stamps. SHA-256, length and mtime are checked across copying and a second successful bounded Cargo verification selecting the same artifact. Both builds, inventory, copying/hashing, every real CLI child, parsing and final validation remain inside the same request deadline. No guessed target path, installed executable, arbitrary executable override or cross-request cache is used.

Deterministic inventories include all source bytes, embedded Markdown/Python, manifest, lockfile, toolchain files, root build-script presence, ancestor manifests and effective Cargo configuration locations. They are compared around acquisition, before later calls and before success. Symlinks, unreadable/special inputs, computed/external embedded inputs and nested conditional module paths decline the optimized route. Unsupported configuration, runner/environment, custom build/target/profile/compiler flags, parent workspace, local/git dependency, dynamic/native runtime linkage and build-script environment use the original per-command source Cargo path. Windows environment-key matching is case-insensitive. This fallback retains known inventory guards and remaining deadline, never replays an operation, and does not claim optimized-route closed-world guarantees for opaque inputs or performance for unsupported contexts.

`src/runtime/command.rs` uses the existing private ProcessTree containment. Its guard owns the child immediately after spawn, then transfers blocking wait and pipe reads to completion-event producers. The caller waits on process exit, pipe EOF or output/read failure under the original remaining deadline, without an ordinary sleep/poll loop or temporary capture files. It retains Windows suspended-start Job Object attachment and Unix process groups; timeout, output overflow, attachment/read/wait errors and unwind keep cleanup ownership. Parent success terminates descendants before output is accepted. The two readers share one atomic 2 MiB output allowance per process, including Cargo, and report overflow promptly. Foreground error cleanup retains its existing 250 ms bound; an exceptional background reaper retains outstanding child/event and Unix descendant reaping ownership. The existing post-termination descendant-reaping fallback remains. All three completion events and an empty contained tree are required before successful output is accepted. Original exit status, text mode and non-JSON failure classification remain.

Final source/deadline checks apply to all four helper families, including task-role configuration/open paths. Transport failure remains an adapter error, not an invented task refusal. Earlier genuine operations may already have occurred; no rollback or zero-effects claim is made. No source comments/docstrings, dependencies, contracts, request budgets, resource-group limits or assertions changed. The explicitly approved dev profile now uses line-tables-only debug information; opt-level 1, debug assertions and overflow checks retain their existing settings. The nextest filter only adds the new transport suite to the existing single-thread group.
